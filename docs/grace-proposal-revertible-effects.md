# Обратимые эффекты в контракте модуля

Черновик предложения команде GRACE. v0.1, 2026-08-25.
Обкатано на реальном проекте (ClaudeBar, GRACE 3, 23 модуля).

---

## Коротко

Предлагаем добавить в `MODULE_CONTRACT` два поля: **`EFFECTS`** — что модуль
меняет за своими границами, и **`REVERT`** — как это откатить.

Это не новая сущность: поле уже стихийно возникает в свободных `NOTE`, когда
автору нужно зафиксировать границу владения ресурсом. Мы предлагаем его
узаконить и сделать проверяемым.

## Проблема: половина парадигмы

GRACE хорошо решает **пространственную** задачу композиции: `DEPENDS` плюс
`knowledge-graph.xml` дают декларацию зависимостей и граф, по которому видно,
кто на кого опирается.

Но у композиции есть вторая ось — **временная**: что остаётся в системе, когда
модуль удаляют. Сейчас про это в контракте нет ни слова, и следствие
предсказуемо: обязательство «убрать за собой» **негде объявить, поэтому его
никто и не выполняет**.

Важно: дело не в небрежности. Каждый эффект по отдельности пишется осознанно и
правильно. Теряется он на удалении — там, где про него уже никто не помнит.

## Доказательство: что осталось бы после удаления ClaudeBar

Мы прошли по всем 23 модулям и выписали, что каждый меняет снаружи себя.
Результат (полностью — в `effects-inventory.md`):

- каталог `%APPDATA%\claudebar\` целиком: две базы SQLite с WAL-файлами,
  растущий без ротации `voice.log`, история поиска, три подкаталога;
- `claudebar.ini` рядом с уже удалённым исполняемым файлом;
- **правки в чужих `settings.json` VS Code и Cursor** — подменённый
  `window.title`, отката нет, а бэкап перезаписывается при каждой записи, то
  есть исходное значение теряется после второго вызова;
- **блоки хуков в `~/.claude/settings.json` и `~/.kimi-code/config.toml`** —
  после удаления они зовут несуществующие скрипты;
- возможно не остановленный Docker-контейнер.

Штатного удаления в проекте **нет ни одного**.

Последние два пункта — не мусор, а поломка чужих программ. Именно они и
показывают, что задача не косметическая.

## Три класса эффектов

У них разная цена ошибки, и откат устроен по-разному:

| Класс | Что это | Как откатывать |
|---|---|---|
| **своё** | то, что мы создали целиком и чем владеем | удалить |
| **чужое** | правка в файле, которым владеет кто-то другой | вернуть **ровно нашу часть**, не тронув остальное |
| **процесс** | запущенное нами и живущее дольше нас | остановить |

Класс «чужое» — самый опасный и самый интересный. Здесь «удалить файл» — это
не откат, а новая поломка.

## Предлагаемый синтаксис

```
// START_MODULE_CONTRACT
//   PURPOSE: ...
//   SCOPE: ...
//   DEPENDS: M-WINENUM
//   EFFECTS: своё:    создаёт %APPDATA%\claudebar\signals\; удаляет оттуда *.signal
//            чужое:   —
//            процесс: —
//   REVERT:  удалить каталог signals\ целиком
//   LINKS: M-SIGNAL
// END_MODULE_CONTRACT
```

Для «чужого» откат обязан быть точечным:

```
//   EFFECTS: чужое: ключ "window.title" в settings.json VS Code и Cursor
//                   (бэкап settings.json.claudebar-bak)
//   REVERT:  вернуть прежнее значение из бэкапа; если бэкапа нет — удалить
//            ТОЛЬКО наш ключ, файл целиком не перезаписывать
```

Модуль без внешних эффектов пишет `EFFECTS: none` — это тоже полезная
информация: значит его можно удалять свободно.

## Как это включается в уже работающие механизмы

Ничего нового строить не надо, всё встраивается в существующее:

- **`grace-reviewer`** — расширение оси «Соблюдение контрактов»: у каждого
  объявленного эффекта есть откат; и обратно — в коде нет записи наружу, не
  объявленной в `EFFECTS`. Ловится поиском по файловым и реестровым вызовам.
- **`verification-plan.xml`** — точка верификации нового вида: «поставить →
  поработать → откатить по `REVERT` → система в исходном состоянии».
- **`knowledge-graph.xml`** — элемент `<external-effects>` рядом с `<depends>`.
  Эффекты становятся рёбрами «модуль → ресурс», и граф начинает отвечать на
  вопрос «кто ещё трогает этот каталог» — то есть ловит конфликты владения.
- **`grace lint`** — тривиальная проверка: `EFFECTS` не `none`, а `REVERT`
  пуст → ошибка.
- **`grace-refactor` / `grace-execute`** — главная выгода. Агент, удаляющий
  модуль, **читает `REVERT` и выполняет его**, вместо того чтобы догадываться.

## Почему это особенно важно для агентов

Человек, работавший с проектом год, помнит про каталог в `%APPDATA%`. Агент —
нет. Он видит только то, что записано.

Сейчас при удалении модуля агент вынужден реконструировать эффекты из кода —
и промахивается тем вернее, чем аккуратнее эффект спрятан за абстракцией.
Записанный `REVERT` превращает догадку в исполнение.

## Чем это отличается от Cordis

Идея не наша. Она формализована в статье
[_A Programming Paradigm for Spatiotemporal Composability_](https://github.com/cordiverse/paper)
(Cordis, август 2026), на которой построен DeepSeek Harness. Там **рантайм**
сам ведёт обратную операцию для каждого изменения контекста — забыть
физически невозможно.

GRACE — не рантайм, а методология сборки кода, и такой гарантии дать не может.
Наша планка ниже и честнее: обязательство должно быть **записано и
проверяемо**. Забыть по-прежнему можно — но уже не молча.

## Ограничения, которые стоит признать сразу

- Проверка «в коде нет необъявленных эффектов» полнотой не обладает: эффект
  можно спрятать за абстракцией или внешней библиотекой. Ловим типовые случаи,
  не все.
- `REVERT` прозой не исполняется автоматически. Следующий шаг — машинная форма
  (список путей и команд), но начинать стоит с прозы: она сразу даёт пользу
  ревьюеру и агенту.
- Поля стоят человеко-времени на каждом модуле. Оправдано для того, что имеет
  эффекты; для чистой логики это одна строка `none`.

## Что уже сделано

- Инвентарь эффектов по всем 23 модулям ClaudeBar — `effects-inventory.md`.
- Поля `EFFECTS`/`REVERT` проставлены в контрактах M-SETTINGS, M-CONFIG,
  M-INDEX, M-VOICE, M-SIGNAL, M-SEARCHBOX, M-SDAEMON.
- Побочный результат: сама инвентаризация нашла долги, которых никто не искал —
  отсутствие ротации у `voice.log`, потерю исходного `window.title` при
  повторной записи, отсутствие деинсталлятора хуков.

Последнее — аргумент сам по себе: поле окупилось до того, как заработала хоть
одна проверка.
