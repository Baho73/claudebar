# Декларация внешних эффектов и плана отката в контракте модуля

Предложение команде GRACE. **v0.3, 2026-08-25.**

История: v0.1 — под GRACE 3; v0.2 — под GRACE 4; v0.3 — после разбора, который
нашёл в v0.2 внутреннее противоречие, неработающий формат и конфликт имён.
Что изменилось, перечислено в конце.

> Для отправки в апстрим нужен перевод на английский: `osovv/grace-marketplace`
> англоязычный.

---

## Коротко

1. Поднять существующее поле **`SIDE_EFFECTS`** с уровня функции на уровень
   модуля: что модуль меняет за своими границами.
2. Добавить поле **`REVERT_PLAN`**: как это откатить.
3. Сделать `SIDE_EFFECTS` обязательным полем контракта модуля; `REVERT_PLAN` —
   обязательным условно, отдельным правилом.

Новых понятий не вводится: поле про внешние эффекты в GRACE уже есть.

## Почему это нужно: аргумент из вашего же кода

В `skills/grace/grace-explainer/references/semantic-markup.md` описано поле
контракта функции:

```
SIDE_EFFECTS: [What external state it modifies]
```

Там же — прямой запрет его переименовывать. То есть **необходимость объявлять
внешние эффекты в GRACE уже признана**.

Но контракты функций разбираются, а их поля не валидируются нигде: обязательны
только четыре поля модуля (`PURPOSE`, `SCOPE`, `DEPENDS`, `LINKS`). Значит поле
про внешние эффекты **существует и не проверяется** — ровно то состояние, в
котором декларация постепенно расходится с кодом, и никто этого не замечает.

Предложение — не изобрести поле, а достроить то, что уже есть: поднять на
уровень модуля (эффект принадлежит модулю, а не одной функции), добавить вторую
половину (чем откатывать) и включить проверку.

## Чего не хватает в модели: временная ось

`DEPENDS` плюс граф в `.grace/graph/` описывают, **кто на кого опирается**.
Не описано, **что остаётся в системе, когда модуль удаляют**.

Следствие: обязательство «убрать за собой» негде объявить, поэтому его никто и
не выполняет. Дело не в небрежности — каждый эффект по отдельности пишется
осознанно. Теряется он на удалении, где про него уже не помнят.

## Что такое внешний эффект

Определение нужно, иначе поле нефальсифицируемо: ревьюер не сможет сказать
«здесь неверно», только «мне кажется».

> **Внешний эффект** — изменение состояния, которое (а) переживает завершение
> нашего процесса и (б) наблюдаемо тем, кто не читал наш код.

Уточнения:

- **чтение эффектом не является**;
- ресурс, созданный другим модулем **этого же** проекта, для нас чужой: в
  `SIDE_EFFECTS` его объявляет только модуль-владелец, остальные ссылаются на
  владельца.

### Тест из трёх вопросов

1. **Останется ли след?** После завершения процесса и удаления наших файлов
   остаётся ли что-то изменённым, что видно постороннему? Нет → `none`.
2. **Можем ли вернуть прежнее значение своими силами?** Есть ли сохранённое
   прежнее состояние и переживает ли оно повторный запуск? Нет → эффект
   **необратим**, и это надо написать прямо.
3. **Кто владеет целью?** Только мы / другая программа / общий слот системы
   (порт, горячая клавиша, буфер обмена) / удалённая сторона.

## Классы эффектов

| Класс | Что это | Форма отката |
|---|---|---|
| `своё` | создали целиком и владеем | удалить |
| `чужое` | правка в файле, которым владеет кто-то другой | вернуть ровно нашу часть |
| `процесс` | запущенное нами, живёт дольше нас | остановить |
| `иное` | не попало ни в один класс | описать словами |

Класс `чужое` — самый опасный: здесь «удалить файл» это не откат, а новая
поломка.

Класс `иное` обязателен как предохранитель. Два случая `иное` в одном
проекте — повод завести класс, а не расширять прозу. На пилотном проекте такой
случай нашёлся ровно один: буфер обмена — общий временный слот, где откат
означает «восстановить прежнее содержимое», а не «удалить».

Если классов окажется мало, разумное развитие — классифицировать не по виду
вещи, а по виду отката (создано / изменено / занято / запущено / удалённое /
необратимо). В этом предложении такой переделки нет: сначала стоит проверить,
хватает ли четырёх.

## Формат: строго одна строка на поле

Это не стилистика, а требование разборщика. В `src/project-utils.ts:497`:

```ts
const match = stripCommentPrefix(line).trim().match(/^([A-Z_]+):\s*(.*)$/);
```

Поле открывает только строка, начинающаяся с латинских заглавных и двоеточия.
**Всё, что записано продолжением, молча отбрасывается.**

Проверено на пилоте: в одном контракте из восьми строк терялось пять, включая
единственное упоминание обязательства снять хуки из чужих конфигов. То есть
поле, заведённое ради того, чтобы обязательство не терялось, теряло его само.

Два следствия:

- в предложении формат — **одна строка на поле**, классы разделяются точкой с
  запятой;
- это касается не только новых полей. На том же проекте так же теряются
  продолжения `NOTE` и `SCOPE` в существующих контрактах. Дефект общий, и
  замечен он был только потому, что содержимое полей начали проверять.

Примеры:

```
//   SIDE_EFFECTS: своё: создаёт %APPDATA%\app\signals\ и удаляет оттуда *.signal; чужое: файлы *.busy пишут внешние хуки, владение общее
//   REVERT_PLAN: удалить каталог signals\; отдельно снять блоки хуков из ~/.claude/settings.json — иначе зовут несуществующие скрипты
```

```
//   SIDE_EFFECTS: чужое: ключ "window.title" в settings.json редактора; рядом кладём бэкап settings.json.app-bak
//   REVERT_PLAN: вернуть window.title из бэкапа; без бэкапа — удалить ТОЛЬКО наш ключ, файл не перезаписывать
```

```
//   SIDE_EFFECTS: none
```

### Значение «откатить нельзя»

Правило «объявил эффект — объяви откат» без этого заставляет писать ложь.
Пример с пилота: бэкап настроек редактора перезаписывается при каждой записи,
поэтому со второго вызова исходное значение физически потеряно. Под давлением
линтера автор напишет «восстановить из бэкапа» — и агент это исполнит.

> Допустимое значение: `REVERT_PLAN: необратимо — <причина>; компенсация: <что делаем вместо>`.
> Линтер такое принимает, но помечает предупреждением, чтобы необратимые эффекты
> были видны списком.

## Точка внедрения

**Обязательным делается только `SIDE_EFFECTS`:**

```ts
for (const field of ["PURPOSE", "SCOPE", "DEPENDS", "LINKS", "SIDE_EFFECTS"]) {
```

`REVERT_PLAN` проверяется отдельным правилом:

```
markup.effects-without-revert-plan —
  SIDE_EFFECTS после нормализации не равно "none", а REVERT_PLAN пуст
```

Почему именно так: если сделать обязательными оба поля, то, во-первых, обещание
«для чистой логики достаточно одной строки `none`» перестаёт работать, а
во-вторых, отдельное правило становится мёртвым кодом — до него никогда не
дойдёт очередь. В v0.2 этого предложения были ровно обе ошибки.

**Нормализация.** Поле считается пустым, только если всё значение после обрезки
пробелов и приведения к нижнему регистру равно `none`. Прочерки внутри значения
на это не влияют. `REVERT_PLAN` считается заполненным, если он не пуст и не
равен `none`, `—`, `tbd`, `todo`.

**Что ещё придётся тронуть** (в v0.2 было сказано «больше менять нечего» — это
неверно): каталог сообщений об ошибках, документацию CLI, тесты, шаблоны
контрактов и примеры, промпт ревьюер-субагента, мигратор GRACE 3 → 4 (ему нужно
что-то подставлять в новое обязательное поле).

## Что мы наблюдали на одном проекте за один день

Пилот: панель на Rust + Win32, 23 модуля, автор предложения — он же автор кода
и он же судья в спорных случаях. Это важно при чтении.

**1. Заполнение поля вскрыло три незаписанных обязательства.** Лог без ротации;
бэкап чужих настроек, затирающий сам себя со второго вызова; отсутствие
деинсталлятора у хуков, из-за чего после удаления программы чужие конфиги зовут
несуществующие скрипты.
*Показывает*: разовый обход по модулям окупается.
*Не показывает*: что окупается именно постоянное поле — разовый аудит дал бы
тот же результат и стоил бы один раз.

**2. Разметка без проверки деградирует.** Миграция проекта на GRACE 4 вскрыла
разом 20 ошибок разметки. Обе цифры — 20 ошибок и `lint = 0` после починки —
выданы вашим CLI, не автором.
*Показывает*: без проверки разметка расходится с кодом.
*Не показывает*: что деградирует именно это поле.
*Соперничающее объяснение*, которое надо назвать честно: проект был на GRACE 3,
и линтер отказывался его валидировать — то есть проверки не было **никогда**, а
не «была и протухла». Проект без линтера мало говорит о судьбе конвенции с
линтером.

**3. Формат теряет данные молча.** Продолжения строк отбрасывались разборщиком —
и в новых полях, и в существующих `NOTE` и `SCOPE`. Замечено только тогда, когда
содержимое полей начали читать машиной.
*Показывает*: то, что не проверяется, тихо ломается даже без участия человека.

### Чего мы не наблюдали

Ни одного заполнения не автором предложения. Ни одного цикла ревью с чужим
ревьюером. Ни одного реально исполненного отката по записанному плану. Ни одного
случая, где классификация не сработала — что скорее говорит об узости пилота,
чем о полноте классов.

### Проверка за час, не требующая нам верить

Возьмите один свой проект и выпишите внешние эффекты по модулям. Это час-два.
Если не найдётся ни одного незаписанного обязательства — в вашем контексте поле
не окупается, и предложение стоит отклонить.

## Риск, который мы добавляем

Заявленная выгода — «агент читает план отката и исполняет его» — это же и новый
режим отказа: **устаревший план означает агента, исполняющего неверное удаление
в чужом файле**. Автоматическое разрушающее действие на основании прозы, которую
никто не сверял с кодом.

Смягчение, которое стоит записать правилом сразу:

- агент сначала печатает список того, что тронет, и только потом трогает;
- для классов `чужое` и «необратимо» автоматическое исполнение запрещено по
  умолчанию.

Второй риск честнее назвать сразу: обязательное поле ломает линт у всех
существующих проектов. Разумный путь — сначала предупреждением, ошибкой со
следующей мажорной версии.

Третий: постоянная стоимость лежит не на написании, а на **ревью**. Чтобы
подтвердить `none`, ревьюер обязан прочитать модуль. Это на каждый модуль,
навсегда.

## Что не заявляется

Идея заимствована из работы про композицию во времени и пространстве
([Cordis](https://github.com/cordiverse/paper), август 2026), на которой
построен DeepSeek Harness. Там рантайм сам ведёт обратную операцию.

Здесь — **объявленное обязательство, исполняемое человеком или агентом, а не
гарантированная рантаймом обратная операция**. Конкретно не заявляются три
свойства оригинала:

1. **гарантия исполнения** — план может не сработать;
2. **композиция** — откаты не складываются автоматически; порядок надо задавать
   отдельно (разумный умолчательный — обратный `DEPENDS`);
3. **тотальность** — откат есть не у всякого эффекта, часть необратима.

Поэтому и название поля — `REVERT_PLAN`, а не `REVERT`: суффикс говорит, что это
план, а не исполняемая команда. В v0.2 поле называлось `REVERT`, а заголовок —
«обратимые эффекты»; имя обещало гарантию, которой нет. Имена путешествуют по
диффам, оговорки в разделах — нет.

## Ограничения

- Проверка ловит **пустоту**, а не **правду**: расхождение объявленного эффекта
  с кодом синтаксически не обнаружимо. Это осознанный первый шаг, а не решение.
- План отката прозой не исполняется автоматически. Машинная форма (список путей
  и команд) — возможное развитие, не часть предложения.
- План должен быть безопасен при повторном запуске и при отсутствии цели:
  «нечего откатывать» — успех, не ошибка.
- Механизм не достаёт до файлов вне зоны контрактов. На пилоте самый опасный
  эффект — правка чужих конфигов агентов — производится вспомогательными
  скриптами вне `src`, у которых контракта модуля нет. Поля в контрактах этот
  случай **не закрывают**, и это надо решать отдельно.
- Предлагаются **только** два поля и одно правило. Всё остальное — идеи без
  обязательств. Первую итерацию автор готов сделать сам.

## Что изменилось с v0.2

- имя поля: новое `EFFECTS` → существующее `SIDE_EFFECTS`, поднятое на уровень
  модуля; конфликт имён снят;
- `REVERT` → `REVERT_PLAN`; «обратимые эффекты» убраны из заголовка;
- починено противоречие: обязательным становится одно поле, не два;
- формат зафиксирован однострочным — многострочный физически не работал;
- добавлено значение «необратимо»;
- свидетельства переписаны с разделением «показывает / не показывает»,
  добавлены соперничающее объяснение и раздел «чего мы не наблюдали»;
- убрано свидетельство про конвенцию, подхваченную соседней сессией: свидетель
  находился в том же репозитории, где конвенция и родилась, — независимости нет;
- добавлен раздел про риск, который предложение создаёт;
- убран список «непокрытых» классов эффектов: сверка с инвентарём его не
  подтвердила, честный случай остался один.
