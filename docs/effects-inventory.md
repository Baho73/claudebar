# Инвентарь внешних эффектов

Что каждый модуль меняет **за своими границами** и убирает ли за собой.
Составлено 2026-08-25 как основа для полей `EFFECTS` / `REVERT` в `MODULE_CONTRACT`.

Мотив: сейчас обязательство «убрать за собой» нигде не записано, поэтому его
никто не выполняет — не по небрежности, а потому что его негде объявить.

## Что останется после удаления программы

1. Каталог `%APPDATA%\claudebar\` целиком: две базы с WAL-файлами, растущий
   `voice.log`, история поиска, каталоги `signals\`, `mail\`, `mail-icons\`.
2. `claudebar.ini` рядом с удалённым исполняемым файлом.
3. **Чужие файлы с нашими правками**: `settings.json` VS Code и Cursor с
   подменённым `window.title` плюс мусорные `.claudebar-bak`.
4. **Чужие конфиги агентов**: блоки хуков в `~/.claude/settings.json` и
   `~/.kimi-code/config.toml`, зовущие уже несуществующие скрипты.
5. Возможно не остановленный контейнер `whisper-dictate`.

Пункты 3 и 4 — единственные по-настоящему опасные: мы оставляем поломанными
чужие программы. Остальное — мусор, который просто занимает место.

## Классификация эффектов

Для будущей схемы полезно различать три класса — у них разная цена ошибки:

- **СВОЁ** — то, что мы целиком создали и чем владеем (`%APPDATA%\claudebar\`).
  Откат: удалить.
- **ЧУЖОЕ** — правки в файлах, которыми владеет кто-то другой (настройки
  редакторов, конфиги агентов). Откат: вернуть **ровно нашу** часть, не тронув
  остальное. Здесь и нужен настоящий обратимый эффект, а не «удалить файл».
- **ВНЕШНИЙ ПРОЦЕСС** — запущенное нами и живущее дольше нас (контейнер,
  демон, хоткей). Откат: остановить.

## Предлагаемые поля контракта

```
//   EFFECTS: своё:   создаёт %APPDATA%\claudebar\signals\, пишет *.signal
//            чужое:  —
//            процесс: —
//   REVERT:  удалить каталог signals\ целиком
```

Для «чужого» откат обязан быть точечным:

```
//   EFFECTS: чужое: ключ window.title в settings.json VS Code и Cursor
//                   (бэкап settings.json.claudebar-bak)
//   REVERT:  вернуть прежнее значение window.title из бэкапа; если бэкапа нет —
//            удалить только наш ключ, файл не трогать
```

(проект на GRACE 3, CLI версии 4 отказывается его валидировать), поэтому
разметка держится исключительно на внимательности человека.
