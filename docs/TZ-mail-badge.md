# ТЗ: индикатор входящих в ClaudeBar (модуль M-MAIL)

Статус: готово к реализации. Поставщик данных (роутер входящих) уже работает
и пишет сигналы — ClaudeBar их только читает и рисует.

## Зачем

Письма и сообщения из мессенджеров раскладываются по папкам проектов внешним
роутером (`D:\Python\mail-mcp`, репозиторий `Baho73/mail-mcp`). Нужно видеть в
панели, в какой проект что-то прилетело — **и для живых сессий, и для проектов
в разделе «Недавние»**, где сессия не запущена. И запускать сессию оттуда же.

## Что уже есть на входе

Роутер кладёт по одному файлу на проект в `%APPDATA%\claudebar\mail\<hash>.mail`
(`hash` = sha1 от пути в нижнем регистре, первые 16 hex-символов):

```
cwd=D:\Python\_inbox\бухгалтерия
count=7
sources=mailru:6,yandex:1
```

- `cwd` — папка проекта; сопоставляется со строкой панели
- `count` — сколько неразобранного всего
- `sources` — разбивка по источникам: `ключ:количество`, через запятую

Файл **существует ровно пока есть неразобранное**. Разобрал (файл ушёл из
`<проект>\.inbox\`) → роутер сам удаляет сигнал на следующем прогоне. Значок
гаснет не когда открыли сессию, а когда работа сделана.

Ключи источников (пополняемо, брать из файла как есть):
`mailru`, `yandex`, `gmail`, `sca_order`, `sca_info`, `sca_admin`, `custombot`
(это почтовые ящики), `telegram`, `max`.

Живые примеры сейчас:

| Папка | count | sources |
|---|---|---|
| `D:\Python\_inbox\бухгалтерия` | 7 | `mailru:6,yandex:1` |
| `D:\Python\stroykontrol-ai` | 4 | `sca_order:2,telegram:2` |
| `D:\Python\ConstructMan\Shale` | 4 | `max:4` |
| `D:\Python\margo-ai` | 2 | `telegram:2` |

## Что сделать

### 1. Модуль `src/mail.rs` (M-MAIL) — чтение сигналов

Полная калька с `signal.rs`, механика уже отлажена:

- `mail_dir()` — `%APPDATA%\claudebar\mail\`, создавать при отсутствии
- скан папки раз в секунду в общем тике (`main.rs:1258`, `SetTimer(hwnd, 1, 1000)`)
- TTL **не нужен**: файл живёт, пока есть работа (в отличие от `.busy`)
- разбор построчный `ключ=значение`, к лишним/новым ключам быть терпимым
- тип: `Mail { cwd: String, count: u32, sources: Vec<(String, u32)> }`
- поле в `App` (`state.rs:33`), заполнение в `refresh_items()` (`main.rs:162-166`)

### 2. Сопоставление сигнала со строкой панели

**Готовое не переписывать**: `signal::sess_matches_row(cwd, key, row_path, row_name)`
(`signal.rs:376`) уже решает ровно эту задачу — вложенные папки, коллизии
одноимённых проектов (дефект D-06), регистронезависимость.

- строка окна: путь берётся из `WinItem.path` (`win_enum.rs:51`)
- строка «Недавнего»: путь лежит в `OpenCmd::Editor.folder`, достаётся
  хелпером `recent_path()` (`main.rs:744`). Сейчас «Недавние» матчатся по
  basename — для писем **матчить по полному пути**, структуры менять не нужно

### 3. Отрисовка: одна ячейка, иконки циклятся

Требование заказчика: **один значок, меняется раз в секунду** по кругу между
источниками (почта → телеграм → MAX → почта…). Не ряд иконок, не счётчики.

- **настоящие логотипы сервисов**, не буквы и не эмодзи; ресурсы в бинарнике
  (по образцу `icon.rs`), размер под строку — ориентир 14×14 при `ROW=30`
- при одном источнике — статичный значок, без мигания
- смена по таймеру: механизм анимации уже есть (`update_anim_timer()`
  `main.rs:171-183`, шаг 350 мс для «бегущих точек»); для иконок нужен шаг 1 с —
  либо отдельный таймер, либо счётчик тиков поверх существующего
- **место в строке окна**: блок квадратов сессий `render.rs:416-461`; значок
  ставить левее квадратов, сдвинув `name_right` (`render.rs:407-413`)
- **место в строке «Недавнего»**: `render.rs:486-501` — там справа пусто
- тултип при наведении: `tooltip.rs`, текст вида
  `7 новых: Mail.ru 6, Яндекс 1` (человеческие названия, не ключи)

### 4. Запуск сессии из панели

Сейчас ClaudeBar умеет только переключаться на существующее окно
(`activate.rs`) — спавна нет.

- пункт контекстного меню «Запустить Claude Code здесь»: новый ID
  (`menu.rs:47-61`, свободны 24-29 и 39+) и ветка в `handle_command()`
  (`menu.rs:129`)
- путь цели — `menu_link_for()` (`main.rs:1014-1028`)
- спавн по образцу `spawn_whisper_start()` (`main.rs:863-874`):
  `Command::new(...)` + `CREATE_NO_WINDOW`, в фоновом потоке
- команду вынести ключом в `claudebar.ini` (как `searchcmd=`), дефолт
  `wt.exe -d <folder> claude`. Путь **обязательно** в кавычках и с валидацией —
  как сделано в `open_in_explorer_select()` (`menu.rs:349`, дефекты D-20/D-21)
- **важно:** запуск сессии значок НЕ гасит. Гасит только разбор входящего.

## Чего НЕ делать

- не трогать `.inbox`-файлы и не удалять сигналы: их жизненным циклом владеет
  роутер, ClaudeBar только читает
- не ходить в `.inbox` каждый тик: обход папок всех проектов раз в секунду —
  это лишние обращения к диску, ради этого и сделан один сигнальный каталог
- не заводить TTL на сигналы

## Проверка

1. `python D:\Python\mail-mcp\router.py --sync` — пересобрать сигналы
2. в панели у 9 папок появляется значок; у `бухгалтерия` иконка чередует
   Mail.ru и Яндекс, у `stroykontrol-ai` — почту и Telegram
3. убрать файл из `<проект>\.inbox\` в `.inbox\done\`, снова `--sync` →
   значок гаснет
4. ПКМ по строке → «Запустить Claude Code здесь» → открывается терминал в
   нужной папке, значок остаётся
